## Red flags
- thread (light and dark) + thread-crisis (light): axe reports 3 "region" violations (landmark not wrapping all content), technically passing but advisory—verify all main content wrapped in `<main>` or sectioned landmark for full screen-reader nav.
- timeline-light: competing focal points at fold (heading + badge + mood grid)—tighten hierarchy so date and "your story" lead.
- memory-card tabs: light mode tab styling diverges from button system (black/white pills instead of outline system).
- B4 glow animation: confirm scoped to meditation pause screen only, not running globally.
- Paywall: "go deeper with you" edges toward vague wellness-speak; tighten for specificity.
- Dark mode meditation pause: Pip glow circle at breathing pacer could read low-contrast on very dark backgrounds (honey #f5b841 on night #1c1a17)—measure actual contrast to confirm ≥3:1 for large text/UI.

## Top 3 fixes (highest leverage first)
1. **Timeline hierarchy.** Move "this week's flow" and mood dots below the fold or de-emphasize the "last 7 days" badge. Let "your story" heading + today's date own the top section. Test with one thumb scrolling on 390px viewport—should land "your story" as single focal point without bouncing eye to three competing elements.
2. **Landmark regions.** Wrap thread Composer (the bottom input area) in a `<form>` or ensure all interactive content on thread and crisis-thread sits inside `<main>` or a labeled region. Test with screen reader (NVDA/VoiceOver) to confirm landmarks announce properly. The axe report notes the issue; resolving it unlocks true WCAG compliance.
3. **Meditation pause glow contrast.** Measure honey #f5b841 on night #1c1a17 actual rendered contrast in the Pip glow circle (likely ≥3:1, but verify). If it dips below, increase brightness or add a subtle night-line border to the breathing ring for definition. Confirm breathing ring animation runs smoothly on all reduced-motion settings (currently testing shows 0 animations under prefers-reduced-motion, which is correct—but test that Pip glow doesn't flicker on pause-screen entry).

## Notes for peers
- The gate baseline is strong: 0 console errors, all Tier A objectives met. Focus rings are visible and well-sized. Accessibility is not an afterthought.
- One thumb on a moving bus: primary actions all in thumb zone (bottom 44px), text all legible at arm's length (min 12px, generous line height on reading). Composer sticky at bottom is the right UX move.
- Screen reader walk: Composer textarea has aria-label "message pip", buttons have aria-labels (add photos, remove photo, send, speak a thought). Settings screen will read as a list of options with secondary text descriptions. Check crisis-thread screen reading — "people who can help, right now" should announce as a live region or alert so urgency lands in audio alone.
- Reduced motion: All animations disabled under prefers-reduced-motion flag. This is correct and tested (0 animations reported on all screens). No motion-dead-UI—breathing Pip, typing dots, fades all turn off cleanly, UI still responsive.
- Dark mode is a true second design, not an inversion. Night background (#1c1a17) gives depth, night-raised (#26231f) surfaces lift off, night-text (#f3ecdd) warm cream on dark. Mood dots (sage, blush, sky) glow slightly against dark. Yellow (honey #f5b841) glows on dark (appropriate glow semantic token swap in globals.css). Tested both themes; hierarchy holds in both.
- Cognitive load insight: Settings screen surfaces "get help now" prominently (warm red callout, not emergency red), which lowers decision burden for someone in crisis—good UX empathy. Crisis thread context also shows this is not an emergency-only app; the tone stays warm even when forwarding to real resources.
- Paywall ethical framing: "not right now" dismiss always visible, no trap, copy honestly explains free vs. paid. This preserves brand trust.
