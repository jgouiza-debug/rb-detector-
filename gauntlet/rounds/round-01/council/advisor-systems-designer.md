## Red flags
- none found; checked: default gradients (only soft sunlight→honey on Pip permitted, never naked #FFDE7A), default Tailwind spacing (all px-* / gap-* map to theme tokens, zero bare Tailwind defaults), color discipline (palette is explicit allowedPairs list, no muddy combos), card grids (memory cards are structured, not repeated filler), generic copy (all text is product-specific), glassmorphism (no blur or frosted glass), typography balance (clear size hierarchy 12/14/16/18/24/32px, generous reading line-height 1.6), spacing breathing (gap-2 = 8px between sections, p-4/p-6 around content). One axe advisory noted: "region" landmark moderate (thread textarea not in <form>) — this is a best-practice advisory, not a WCAG failure, and the message list does have a proper main with role="log" and h1 sr-only. Not blocking.

## Top 3 fixes (highest leverage first)
1. **Wrap the composer in a semantic <form>.** The textarea is currently a generic div child. Wrapping it in `<form>` would resolve the axe "region" advisory and clarify the affordance as a complete form action. This costs 1 line and is a pure win for a11y semantics. (thread-light, thread-dark: Composer component)

2. **Verify dark mode emoji legibility on user bubbles.** The user-bubble color (#FFCF4D honey) remains constant in dark mode. On night background (#1C1A17), yellow text might pop too hard and feel warm when it should glow warmly. Spot-check that the emoji in message text (e.g. "🎉") reads as intended and doesn't feel jarring. If issue found, consider adding a subtle filter or verifying the bubble text is always ink dark (which it is: bubble-user-fg = ink in light and dark mode), so emoji would inherit from the surrounding styled text. Likely not an issue but worth a glance.

3. **Consider adding a visual hint for "swipe to reveal timestamp."** Timestamps are hidden by default and shown on tap. Users on mobile may not discover this. Adding a subtle "(tap for time)" affordance or a small clock icon near timestamps would surface this feature. Alternatively, group messages by time and show timestamps only between groups — less discoverable but works for the chat pattern.
