## Red flags

Vibe-coded checklist (RUBRIC.md) — went through each line against the code and all 26 screens:
- Default/generic gradients: none found. Only gradient in the app is the brand-approved sunlight→honey radial behind Pip (`components/pip/PipMascot.tsx:38-46`), used nowhere else.
- Default framework spacing: none found. `app/globals.css:140-152` deliberately zeroes Tailwind's type scale and rebuilds exactly six sizes; gate's own count is 4px off-grid (the half-step), not "everything the same padding."
- Too many colors/fonts: none found. 3 families / 3 weights / 6 sizes, all gate-verified.
- Repeated card/badge grids as filler: none found. Timeline mixes a large full memory card, a compact list card, and a paywall card — distinct shapes, not one shape stacked.
- Generic SaaS copy: none found. Checked ~15 copy strings across onboarding, thread, paywall, help — none use "unlock," "journey," "powerful," or similar boilerplate.
- Glassmorphism/blur for its own sake: `components/ui/TopBar.tsx:6` and the composer bar (`Composer.tsx:70`) use `backdrop-blur-md` on a sticky bar — functional (keeps the header legible over scrolling content), not a decorative glass card, so not counted as a hit.
- Wrong balance (cramped or floaty): borderline, not counted as a hit — `settings-subscription-light` and `memory-locked-paywall-light` have a large empty region above an anchored bottom CTA. That matches the taste brief's "anchored primary actions" pattern rather than looking accidental, but flagging it here so peers can weigh in if they read it as empty rather than intentional.

Additional accessibility/ergonomics defects found (outside the vibe-coded checklist, inside my A1/A2 lane):
- `components/pause/BreathingPacer.tsx:80` — an invisible, keyboard-focusable "toggle" button with no descriptive name or `aria-pressed`, and no visible control for sighted users to pause the breathing animation at all. See A1 evidence.
- `components/chat/Thread.tsx:26-33` — the composer/textarea live outside the page's `<main>` landmark; this is the real, code-level cause of the axe "region" finding on thread/thread-crisis (light + dark).
- `components/timeline/MemoryCard.tsx:49` vs `components/timeline/CompactCard.tsx:10` — inconsistent tap-area size for the same "open this day" action between the two card types used on the same screen.

## Top 3 fixes (highest leverage first)

1. Wrap `ThreadTopBar` + `MessageList` + `Composer` in a single `<main>` (or give the composer its own labeled landmark) in `components/chat/Thread.tsx` — removes the one real axe violation and stops screen-reader users from having the message input announced as outside all page content.
2. In `components/pause/BreathingPacer.tsx`, replace the invisible `sr-only` "toggle" button with a real, visible pause/play control (icon + `aria-pressed`, dynamic label "pause breathing"/"resume breathing") so the feature exists for everyone, not just keyboard-tabbing screen-reader users who happen to land on it.
3. Make `MemoryCard`'s whole footer row (or the whole card) the tappable link to `/memory/[date]`, matching `CompactCard`'s pattern, so the "open this memory" hit area is generous everywhere in the timeline, not just in the corner on today's/yesterday's cards.

## Notes for peers

- Interaction Engineer: the `bubble-in` animation runs at 380ms (`app/globals.css:170`) — a hair past the 150-300ms band you own; worth your own read on whether that reads as slow in the live thread.
- Taste Critic: check whether the sticky `backdrop-blur-md` on `TopBar.tsx` and the composer bar reads as house style or as blur-because-possible — I read it as functional (legibility under a scrolling list) and didn't count it, but it's borderline enough to want a second opinion.
- Systems Designer: the MemoryCard/CompactCard tap-area inconsistency I flagged under A2 is also a B2 consistency issue — two different interaction contracts for what should be one "day row" component.
- User & Brand Advocate: the reduced-motion CSS makes Pip fully static (no breathe/blink) rather than "still alive but slower," which sits in tension with the design spec's own wording — worth weighing against C2 for those users specifically.
