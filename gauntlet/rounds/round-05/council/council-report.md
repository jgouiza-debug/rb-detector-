# Council report — round 05

## State of the UI

Pip in round 5 is a genuinely well-made product with one structural bug quietly wrecking the composition of nine screens and one copy pipeline quietly wrecking its own payoff. The machine gate is green on all five Tier A rows — 0 axe violations, 0 contrast failures, 83/83 focus indicators, 0/268 undersized targets, 0 console errors, CLS ≤ 0.013, FCP 44–120ms — and that green is earned, not gamed: the type ramp is *structurally* locked (`--text-*: initial` in `globals.css:139` deletes Tailwind's size namespace so an off-ramp size emits no CSS at all), the fonts are self-hosted, the mood palette carries a per-pair WCAG contract in `lib/theme/tokens.ts`, and the crisis surface is one shared `ResourceList` object rendered identically in the thread and on `/help`. The copy could only be Pip — "a whole week, kept.", "kept by pip", "cancel anytime · export and delete stay free, always", and a crisis card that says "i'm a small app, not a person who can keep you safe right now — but there are people who can". Against that: `--pt-safe-min`/`--pb-safe-min` are referenced but never declared, so `.pt-safe`/`.pb-safe` compute to 0px and, sitting later in the same `@layer utilities`, *override* every page's own `py-6`/`py-8` — I measured first ink at y=0 and last ink at y=843 of 844 on real renders; `Bubble.tsx` still wraps every scrollback message in a real `<button>`, so a personal journal announces as a list of 34–45 buttons; the skip link points at a wrapper that contains the header it means to skip; and the keepsake generator moves the user's own last line into a `title` that the two hero cards never render, replacing "but i made it through, and i'm home now" with a stock closer. The craft is real. The seams are in the load-bearing places.

## Rulings on the four claims put to the chair

**1. `components/chat/Bubble.tsx` — every message is a real `<button>`. CONFIRMED. Severity: high, but not a hard cap.** Line 21-23 wraps every message, user and Pip, in `<button type="button" title="tap for the time" aria-expanded>` whose only job is `setShowTime(v => !v)`. Per the gate's own target audit that is 34 interactive targets on `thread` and 45 on `thread-crisis`. A screen reader announces a personal journal as a list of buttons; a keyboard user tabs through dozens of them to reach the composer; the `role="log"` on MessageList is undermined by the form controls inside it. It passes axe (the accessible name is the message text, which is technically valid), so no gate fails and no hard cap trips — but this is the single worst thing in the build for the people the rubric's A1 exists to protect, and round 4's council already docked A1 for it. **It is unfixed after a full round.** It must be gone before any 99 is credible. Fix direction: keep the reveal, drop the semantics — put the timestamp on the group's existing timestamp row, or move the toggle to one non-interactive tap surface per message group rather than a native `<button>` per bubble.

**2. Skip link targets a wrapper containing the top bar. CONFIRMED.** `app/layout.tsx:66` is `<a href="#main" class="skip-link">skip to content</a>`. `app/(app)/layout.tsx:20` is `<div id="main" class="flex min-h-[100dvh] flex-col">{children}</div>`. On the thread route `children` is `Thread`, whose first child is `<ThreadTopBar/>` (`Thread.tsx:26-27`); on the timeline route it is `<TimelineTopBar/>` (`timeline/page.tsx:24`). So activating "skip to content" lands the user immediately before the header it was meant to bypass — the next Tab is the header's own first link. Note the aggravating detail: the correct `<main>` elements *exist* and several routes outside the `(app)` group already carry `id="main"` on them properly (`StepShell.tsx:14`, `help/page.tsx:14`, `sign-in`, `offline`, `goodbye`). Only the `(app)` group — thread, timeline, settings, memory, i.e. the whole logged-in product — has the id on the wrong element. Severity: real; it makes an accessibility affordance a decoration. Fix: move `id="main"` off the `(app)` layout `<div>` onto the `<main>` inside each route.

**3. `.pt-safe` / `.pb-safe` resolve to 0px and override `py-*`. CONFIRMED, and it is the highest-leverage bug in the round.** `globals.css:243-244` reads `padding-top: max(env(safe-area-inset-top), var(--pt-safe-min, 0px))`; `--pt-safe-min` and `--pb-safe-min` are declared nowhere in the tree (grepped; the only hits outside those two lines are compiled `.next` artifacts). On a 390×844 browser viewport `env(safe-area-inset-*)` is 0, so both compute to `0px`. In the built CSS I found `.py-6` at byte 21741 and `.pt-safe` at 34490, both inside the single `@layer utilities{` block that opens at byte 9089 — same layer, identical specificity (0,1,0), later source order wins. The page's own padding is therefore not merely unaugmented, it is **erased**. Measured on the actual renders: first ink at **y=0** on `onboarding-name-light` and `onboarding-focus-light` (StepShell declares `py-8` = 32px); last ink at **y=843 of 844** on `onboarding-name-light`, `settings-subscription-light` and `memory-locked-paywall-light`; and `help-light` shows first ink at y=16 against a 23px bottom gap on a page declaring symmetric `py-6` — the exact asymmetry the bug predicts, because `/help` carries `pt-safe` but not `pb-safe`. Affected: all five onboarding steps, all six settings pages, `/help`, and `MemoryDetail`. **Aggravating:** the comment at `globals.css:234-237` states this bug was already found and fixed ("Unlayered rules beat Tailwind v4's layered utilities, so `.pt-safe` was silently killing `py-8`'s padding-top"). Moving the rules into `@layer utilities` removed the *layer* mismatch but left source order intact, so the fix did not work. The builder should not assume this one is closed.

**4. `lib/adapters/ai/scripted.ts` — dropped title, echo and casing. ALL CONFIRMED. And yes, the seven seeded days do read as seven distinct days.** Taking the two halves separately:
- *The seven days hold.* On `timeline-light-full` I read seven distinct dates (Tue Sep 8 → Wed Sep 2), seven distinct reflections, and mood pills heavy / bright / mixed / calm / tender / bright / heavy. No two days close on the same sentence. The six-deep per-mood closing pools and the `seed`-from-the-day's-own-words are doing real work. This is a genuine improvement and it should be credited.
- *The keepsake itself is broken in three ways.* (a) **Dropped line:** `scripted.ts:119-122` sets `title = sentence(last, 46)` and `body = lines.slice(0, -1)`, so the user's last line leaves the reflection entirely. `CompactCard.tsx` renders `day.title`; `MemoryCard.tsx:26-36` and `MemoryDetail.tsx:96-99` render **only** `.reflection`. So on today's and yesterday's cards — the two the user actually looks at — the user's own ending is deleted. `thread-light` shows the user writing "but i made it through, and i'm home now"; `timeline-light-full` shows the card ending "Not every day has to be more than survived." Yesterday loses "turns out the team was cheering for me the whole time" for "I want to remember this one." (b) **Echo:** confirmed as described in red flag 3. (c) **Casing:** `sentence()`'s regex `(^|[.!?]\s+)([a-z])` capitalises sentence starts only, so `memory-card-light` renders "Big review at work today, i was so nervous going in. I want to remember this one." — lowercase i and capital I in adjacent sentences, at 18px, on the keepsake. Half-edited reads worse than untouched. Additionally `MemoryDetail.tsx:96` prefers `memory.moodLabel` ("Bright & warm") over `mood.label` ("bright"), which is the only Title Case string in the app and is visible on `memory-card-light`.
