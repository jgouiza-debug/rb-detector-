## Red flags
- Checked default/generic gradients: none found. The only gradient is the `sunlight→honey` radial in `PipMascot.tsx` (`#FFE8A0→#FFDE7A→#F5B841`), which is the brand doc's one permitted gradient, used only behind Pip.
- Checked default Tailwind spacing left untouched: none found as a hard violation — the two off-grid tells (12px×4, 4px×130) both trace to specific, explained component decisions (see A3 evidence), not "everything the same padding."
- Checked card-grid filler: none found. Timeline's stacked cards are the actual content list the spec calls for (§3.4), not decorative filler; settings uses labeled rows, not a badge grid.
- Checked glassmorphism/decorative blur: `MemoryDetail.tsx`'s `blur-[3px]` on the locked card is functional (signals "locked," per the code's own comment), not applied because it was possible.
- Soft flag, not scored as a hit: the flat-orange photo placeholders across `thread-light/dark`, `thread-composing-photo-light/dark`, `memory-card-light/dark(-full)`, `timeline-light/dark-full` — real `<img>` elements pointing at `/api/media`, almost certainly seed-data solid JPEGs rather than an app defect, but visually indistinguishable from a broken/placeholder image across five-plus screens. Worth a real-photo pass before this ships as evidence.

## Top 3 fixes (highest leverage first)
1. Swap the seed/demo media for an actual photographic image (or at minimum a warm gradient/pattern placeholder, not a flat fill) before the next round's captures — `thread-light`, `memory-card-light-full`, `timeline-light-full` all currently show a solid honey rectangle where a photo should be, and it's the single biggest "is this real" tell in the whole set.
2. Move the "breathe in…" / "breathe out…" heading in `BreathingPacer.tsx` off `font-reading` onto `font-display`, keeping Fraunces exclusively for memory/timeline surfaces as the brand doc specifies — a two-line CSS-class change that removes the only brand-system crack I found.
3. Capture (or instrument a debug flag for) at least one screenshot each of: a pending/optimistic bubble, a failed-send bubble, and the typing-dots state. The micro-interaction engineering in `threadStore.ts` and `Bubble.tsx` is genuinely good, but zero of the 23 gate screens currently prove any of it renders — that's a real verification gap, not just a nice-to-have.
