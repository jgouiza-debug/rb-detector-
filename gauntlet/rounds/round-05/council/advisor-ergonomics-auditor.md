## Red flags
Checked every category in the RUBRIC checklist against the screens and code:
- Generic gradients: none found — only the brand-permitted sunlight→honey glow behind Pip's avatar (onboarding, pause screen).
- Untouched Tailwind spacing defaults: none — `globals.css` deliberately voids Tailwind's default type scale (`--text-*: initial`) and spacing runs 8/16/24/32 (gate: 95.1% on-8pt).
- Too many colors/fonts: none — gate confirms 6 sizes / 3 families / 3 weights app-wide.
- Repeated card/badge-grid filler: none — timeline's stacked day cards are the timeline's actual content, each with distinct reflection text, not identical filler shapes.
- Generic SaaS copy: none found in any of the 23 screens read.
- Glassmorphism/blur used because it's possible: the one blur in the app (`MemoryDetail.tsx` line 53, `blur-[3px]` on the locked-day preview) is functional — it visually communicates "locked," is `aria-hidden`, and shows only the date, not the real reflection text. Not gratuitous.
- Wrong balance / cramped or floaty spacing: none found.

None of the rubric's vibe-coded categories are hit. My own domain surfaced two real, code-confirmed a11y misses not covered by that checklist (see scorecard A1): every chat bubble is a semantically-inappropriate `<button>`, and the skip-link's target contains the header it's supposed to skip.

## Top 3 fixes (highest leverage first)
1. **Stop making every message a button.** `components/chat/Bubble.tsx` line 21 renders each bubble as `<button onClick={... setShowTime}>`. On a real thread this is dozens of false "button" announcements and tab stops before a screen-reader or keyboard user reaches the composer. Move the timestamp reveal off individual message focus (e.g. a tap-anywhere-in-the-group gesture that isn't a native interactive element, or show timestamps on the group's timestamp row instead of per-bubble) and let `role="log"` read as a stream, not a form.
2. **Fix the skip-link's target.** `app/layout.tsx` line 66 (`href="#main"`) points at `app/(app)/layout.tsx` line 20's `<div id="main">`, which wraps the header too. It currently skips nothing. Point it at the message list / page body, past the repeated header.
3. **Give the one control everyone taps every time some headroom.** The thread's send/mic button is 44×44 exactly (gate primary measurement), the tightest target in an app whose own onboarding CTAs are 56px tall. Bump it a few px past the floor for the control that carries the whole core loop.
