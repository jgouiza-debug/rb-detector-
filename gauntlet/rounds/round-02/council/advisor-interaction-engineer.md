## Red flags
- Checked default/generic gradients: none found. Only gradient in the codebase is the brand-permitted `sunlight→honey` radial behind Pip (`PipMascot.tsx:38-46`); `MemoryDetail.tsx:63`'s `bg-gradient-to-b from-transparent to-bg` is a solid-to-background fade for the locked-card mask, not a decorative hue gradient.
- Checked default/untouched Tailwind spacing: none found — `app/globals.css:140-152` explicitly overwrites Tailwind's default type scale and spacing carries the 8pt discipline the gate measured (95.2%).
- Checked glassmorphism/blur-for-its-own-sake: `MemoryDetail.tsx:53` blurs a locked day's card — functional (signals "it exists, it's just not unlocked"), not decorative. `TopBar.tsx:6` / `Composer.tsx:70` use `backdrop-blur-md` on sticky bars — functional legibility aid, subtle, not flagged, but noted above for peer double-check.
- Checked motion-because-possible: none found. Every animation I read ties to a state change (send, typing, keepsake arrival, breath phase) or an idle-liveness cue (breathe/blink) capped at low opacity/scale deltas; nothing spins, bounces or shimmers without a referent.
- One real (non-blocking) miss: `components/onboarding/StepShell.tsx:17` animates the progress bar's width at **500ms**, outside the rubric's stated 150–300ms band. Not a red flag per the checklist's own list, but it is a measured violation of the band this review was asked to check every transition against.

## Top 3 fixes (highest leverage first)
1. Give `Bubble.tsx` a real pressed state (`active:scale-[0.98]` or a background shift on `:active`) — right now the most-tapped element in the app (every message bubble) gives zero visual confirmation of the tap itself, only the delayed timestamp reveal. One line, matches the pattern already used in `Button.tsx` and `CompactCard.tsx`.
2. Drop `StepShell.tsx`'s progress-bar transition from `duration-500` to something in the 150–300ms band (e.g. `duration-250`) so the one outlier matches the rest of the app's motion language.
3. Reconcile the top-right icon nav (`ThreadTopBar`/`TimelineTopBar`) against the design spec's documented bottom nav — either update the spec or move Thread/Timeline switching into the thumb zone; right now it's a one-off pattern that the rest of the system doesn't otherwise use.
