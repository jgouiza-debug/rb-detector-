## Red flags
Went through the vibe-coded checklist explicitly:
- Default/generic gradients — none found; checked `PipMascot.tsx` (`sunlight`→`honey` radial, the one gradient the brand doc allows) and `app/globals.css` for stray `bg-gradient-to-*` — the only other gradient is the paywall's fade-to-background mask in `MemoryDetail.tsx`, which is functional (blends the blurred card into the page), not decorative.
- Default framework spacing — none found as a systemic issue; the 4px×114 off-8pt values the gate itself reports are a minor drift inside dense screens (thread/timeline), not "everything the same padding."
- Too many colors/fonts / no 70/20/10 — none found; gate confirms 6 sizes / 3 families / 3 weights / 21-of-21 screens on the palette proxy.
- Repeated card/badge grids as filler — none found; timeline is a single vertical list, not a card grid, and settings rows carry distinct icons/copy per row.
- Generic SaaS copy — none found; every string I sampled is Pip-specific and lowercase-voiced.
- Glassmorphism/blur used because it's possible — the only blur in the app (`blur-[3px] saturate-50` on the locked memory card, `MemoryDetail.tsx` line 53) is used to make locked content honestly semi-legible-but-not-readable, and the same element is `aria-hidden`. Purposeful, not decorative.
- Wrong balance (cramped/floaty, oversized/undersized type) — none found in the rendered screens.

Two findings outside that checklist, specific to this persona's mandate (A1/A2), that the machine gate cannot see because it never renders these states:
- `components/chat/Composer.tsx` (photo-attach state, not in `gauntlet/screens.ts`): the "remove photo" button is `size-5` (20×20px) against a 44px floor enforced everywhere else in the file.
- `components/chat/Bubble.tsx` (every message in `thread`/`thread-crisis`): every past message is a focusable `<button>` (34 in `thread`, 45 in `thread-crisis` per the gate's own target audit) purely to disclose a timestamp, with no way to skip past scrollback to the composer — a keyboard/screen-reader user pays a real tab-order cost that a sighted, scrolling thumb does not.

## Top 3 fixes (highest leverage first)
1. Bump the composer's "remove photo" button (`Composer.tsx` line 80) from `size-5` to at least `size-11` (44px), matching the `.tap` utility already used on every sibling control in that file.
2. Give the thread a "skip to composer" affordance (a visually-hidden anchor link right after the `role="log"` region, or `tabindex` cycling on old bubbles) so keyboard/screen-reader users aren't forced through 30+ message buttons to reach the input on a returning-user open, per `thread-light.jpg`'s 34-target scrollback.
3. Wire `Bubble.tsx`'s `aria-expanded` toggle to `aria-controls` pointing at the revealed timestamp `<span>` so the disclosure relationship is machine-readable, not just visually true.
