## Top 3 fixes (highest leverage first)
1. **Stop making every chat message a focusable, self-describing button.** `components/chat/Bubble.tsx:21-39` turns every message — including the entire scrollback — into a `<button aria-label="{sender}: {full text} — tap for the time">`. On `thread-light` that's 35 tab stops, on `thread-crisis` 46, before a keyboard or screen-reader user ever reaches the composer, and it only grows as the thread does. Keep the tap-for-timestamp affordance but make it non-focusable by default (e.g. a single per-thread "show timestamps" toggle, or only the newest message tappable), and add a "skip to compose" landmark so AT users get the same one-gesture jump a sighted scroller already has.
2. **Fix the onboarding progress bar's screen-reader value.** `components/onboarding/StepShell.tsx:11,16`: `aria-valuenow={step}` / `aria-valuemax={total}` reports a different percentage (25/50/75%) than the rendered bar width, which uses `(step+1)/(total+1)` (40/60/80%) on 3 of the 4 step screens. Either report `aria-valuenow={step+1}` to match the visual, or add `aria-valuetext` with the real percentage.
3. **Give the "day is ready" link and the memory-card heart proper ergonomics.** `components/chat/SystemMoment.tsx:11-14` is missing the `tap` class every other control in the app carries, computing to ~36px tall — add `tap` (and a press state, matching `PauseChip.tsx`). Separately, `components/timeline/MemoryDetail.tsx:85` puts the only actionable control on the keepsake screen in the top-right corner (`inThumbZone:false` per gate-report.json) — move "mark as resonated" into the card's action row near the bottom, closer to where a one-thumb user's reach naturally lands.
